# Network toolbox

The J701F now has a local, touch-sized network toolbox in Plasma's application menu. Its source is `system/security-toolbox/`; the installed files are under `~/j701f/security-toolbox/`, with a desktop launcher in `~/.local/share/applications/`. It uses Qt Widgets through Alpine's `py3-pyside6`, so the network actions do not need a web service. The phone also has `nmap` and `tcpdump` installed.

The **Refresh** page shows the current IP address, route, cached Wi-Fi list, Bluetooth controller, and USB gadget functions. **Wi-Fi** asks NetworkManager for a fresh scan. **LAN** runs `nmap -sn` against the directly connected Wi-Fi network, capped at the local `/24` even if the connection reports a wider prefix; it does not accept an arbitrary remote target. **Bluetooth** performs a 12-second discovery, then exits. **Capture** records at most 200 packets from `wlan0`, capped to 256 bytes per packet, under `~/j701f/captures/`; the process has a 115-second limit and drops privileges to the phone's user after opening the capture socket. Packet captures can contain private network data and stay on the phone.

The four USB buttons call `usb-profile.sh`. The script changes only optional functions of the existing configfs gadget; ACM serial and MTP remain linked. `USB net on/off` switches the already-created NCM function and rebinds the gadget, so the attached computer briefly sees USB disconnect/reconnect. The on/off cycle was run on the real phone and restored ACM+MTP, NCM off, with the controller bound. `HID on/off` is prepared but **HID on is unavailable in the current kernel** (`CONFIG_USB_CONFIGFS_F_HID` is unset); its preflight fails before disconnecting USB. It sends no keystrokes on its own.

The Wi-Fi controller's advertised modes are managed, AP, IBSS, and P2P; **monitor mode is absent**. The Bluetooth controller starts and discovery found nearby devices; BLE has not been separately validated, and `CONFIG_BT_LE` is unset in the running kernel. The phone loads Broadcom firmware `7.45.98.118`; upstream Nexmon lists bcm43430a1 patches for different `7.45.41.26` and `7.45.41.46` firmware versions, so those patches cannot simply be installed as-is ([Nexmon support matrix](https://github.com/seemoo-lab/nexmon)). USB host mode and NFC are outside this project's current handheld scope.

The installed program was imported and constructed with Qt's offscreen platform. Real Wi-Fi, LAN, Bluetooth, a three-packet capture, and USB NCM on/off were exercised; the temporary capture was deleted. The health check immediately after those toolbox tests showed native display, Plasma, Wi-Fi, serial+MTP, no pending start-up guards, and no kernel oops. The owner has not yet judged the toolbox's visual layout on the phone screen.

**AP experiment, 2026-10-18:** A 30-second NetworkManager hotspot trial failed before `dnsmasq` was installed; the saved home connection returned. After installing `dnsmasq`, a second bounded trial interrupted SSH, but the scheduled independent restore did not return the phone to its known home address within the expected time. AP controls have therefore been removed from the toolbox source and the experimental script now refuses to start without a separate explicit marker. The phone's post-trial state awaits direct confirmation; do not describe AP as working.

**Offline work while phone access is pending:** The source now also has a 20-port check limited to an IPv4 address in the same local Wi-Fi subnet and an explicit USB text sender. The sender accepts at most 160 US-layout ASCII characters, emits separate press/release reports, and has no preloaded payloads. These newer UI files are **not yet deployed** to the phone. A BOOT candidate enabling configfs HID and basic Bluetooth LE (without ECRED) has been built but **not flashed**: `build/kernel/boot-update-hidble2-basecam5/boot-mainline.img`. It reuses the exact installed `cam5` DTB and initramfs byte for byte. Embedded FIT/container guards and QEMU's first Linux instruction passed; 263 host tests passed with GCC. The computer's Clang 22 and compiler-rt 23 mismatch prevents the sanitizer tests from linking under Clang. Phone boot, HID enumeration, BLE and button behavior remain unverified.
